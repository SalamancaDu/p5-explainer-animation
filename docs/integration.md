# 与 design-to-explainflow 配合

[design-to-explainflow](https://github.com/SalamancaDu/design-to-explainflow) 提供解释任务、版式、视觉素材、标题、动效与质量审阅方法。本项目可作为纯代码短动画的实现选择，独立使用时也不依赖另一套 Skill。

内部对象需要独立变化、代码绘制能表达主题时，可以在逐元素动效路线使用本项目。仅为完成一个短动画，无需加载所有设计阶段。摄影真实感、整段视频剪辑或精确数据图表等需求，应按实际目标选择工具，不强制套入三种画风。

## 最小交接

传递原文及不可改内容、观众应理解的关系、已选风格、画幅与时长、已有资产、需要交付到 HTML 还是实际视频，以及用户保留的审阅节点。已有清楚的简报直接引用，不重复采访。

本项目返回实际文件、画面表达、播放 / 导出方式及已执行检查。默认纯代码绘图，不接收整图后冒充逐元素控制；默认静音，不将口播文字当成已有音轨。

参考交接：

```text
解释目标：六段素材如何分成两组，每组三段。
事实：这是自拟演示，物件总数保持六个。
视觉：纸片从分散到归组，两组使用共同排列方式。
规格：1920×1080，六秒，静音。
交付：HTML、末帧 PNG、实际 WebM，并检查数量和录制。
```

两个仓库各自维护自身方法和工具；通过简报、文件与链接连接，不复制彼此整套规则，不自动同步全局安装目录。
